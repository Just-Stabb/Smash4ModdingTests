# Smash 4 Wii U online play today (real Wii U and Cemu): architecture, Nintendo Network shutdown, Pretendo, Cemu

Research date: 2026-10-23. Access notes: pretendo.network (site, docs, blog, progress page), forum.pretendo.network, cemu.cfw.guide, wiki.cemu.info and wiki.pretendo.zip were **unreachable from the research environment** (proxy 403 / DNS failure). Their content appears below only where a search-engine snippet quoted it, and each such item is marked "(search snippet)". The primary sources read in full were Pretendo's own GitHub server code for Smash 4 Wii U (raw.githubusercontent.com), Cemu's source code on GitHub, SmashWiki raw wikitext, Wikipedia raw wikitext, and Kinnay's NintendoClients wiki.

## 1. Smash 4 Wii U netcode model (P2P vs server, delay-based lockstep, input delay, lag, host/client, what is exchanged, NEX/PIA)

### Takeaway
Smash 4's matches run peer to peer over Nintendo's Pia library. NEX game servers only handle login, matchmaking, NAT-traversal brokering, rankings, replays and other data storage. Gameplay is **delay-based lockstep**: every console must have every player's input for a frame before it can simulate that frame, so a late input stalls or slows the game for everyone. Prediction and rollback are never used. The game has a fixed built-in input delay (community measurement: about 7 frames end to end, in every mode including offline). No public source documents Smash 4's exact online input buffer depth or its Pia version.

### Cited Findings
**Netcode model (community and wiki level, no Nintendo documentation)**
- SmashWiki says the series "has historically used a 'delay-based' netcode... the game pausing on both ends until a player's given input is communicated to and confirmed on the opponent's side, usually combined with an artificial delay of a couple frames to give time for inputs to arrive without having to stutter constantly." In good conditions this gives "noticeable gameplay lag"; in worse conditions, "stuttering and (in extreme circumstances) hangs and disconnections." — [SmashWiki: Online desynchronization](https://www.ssbwiki.com/Online_desynchronization)
- SmashWiki also says: "Online modes were given an artificial delay starting in Brawl, while Smash 4 and Ultimate make the delay persist into offline modes." — [SmashWiki: Online desynchronization](https://www.ssbwiki.com/Online_desynchronization)
- Per-frame input exchange: "The player's system must send what their input currently is every frame (60 per second in the Smash series)... If at least one system has not received the input yet, the game must wait until it gets the input, causing lag. The game attempts to compensate... by intentionally not acting upon the input for a few frames; this is the frame delay." — [SmashWiki: Frame delay](https://www.ssbwiki.com/Frame_delay)
- No prediction or rollback: "In the Super Smash Bros. series, the system requires the exact position and action of every element of gameplay before it can do anything, and it is not possible to undo incorrect guesses; as exact consistency must be enforced 60 times every second, tiny amounts of lag can have a massive effect." This is contrasted with Mario Kart, which predicts other players' positions. — [SmashWiki: Wi-Fi lag](https://www.ssbwiki.com/Wi-Fi_lag)
- Inputs are the main data exchanged, but load-state messages are sent too: "When playing online, the games send information about the actions performed, mostly, but they can also send information that needs to be loaded." Example: when a Final Smash loads on one console, it messages the others that it has loaded. A console that believes no Smash Ball was opened treats that message as an error, and "After around 10 seconds, both ends acknowledge that a desynch has occurred, and all players are disconnected." — [SmashWiki: Online desynchronization](https://www.ssbwiki.com/Online_desynchronization)
- Desync detection for mods: "All Smash games with an online mode can disconnect players when it detects a desynch." Also: "In for Wii U and Ultimate, the player using a hack is instantly disconnected from the match upon using a move that could desynchronize the game." Players running "identical hacks generally do not cause a desynch"; texture hacks carry little risk, "model hacks are very likely, and moveset and physics hacks are nearly guaranteed to desynch." — [SmashWiki: Online desynchronization](https://www.ssbwiki.com/Online_desynchronization)
- Bad connections: in For Glory, "In rare instances in which a connection was especially bad between the players with constant pauses that do not cease, the game may have disconnected all players without penalty and automatically ended the match in a no contest." A player who disconnected mid-match was replaced by a low-level AI. — [SmashWiki: For Glory](https://www.ssbwiki.com/For_Glory)
- Lag in 1v1 vs groups: For Glory 1v1 "being the only way to play 1v1 and thus be far less susceptible to lag." — [SmashWiki: For Glory](https://www.ssbwiki.com/For_Glory)

**Input delay figures (they conflict)**
- "In Super Smash Bros 4, seven frames of delay between pressing the button and the game actually outputting the respective action are always present, regardless of gameplay mode." The page cites a YouTube measurement (youtu.be/9nT2VOLwrqk). By comparison, Ultimate has about 6 frames base plus "at least 4 frames of delay... in online matches." — [SmashWiki: Frame delay](https://www.ssbwiki.com/Frame_delay)
- SmashWiki's Display lag page lists an average of **3 frames** for Smash 4 Wii U (search snippet). A Day One Patch forum post claims "4.5+ frames average" (search snippet, community-sourced). These figures probably measure different things (game-internal lag vs end-to-end with display) and conflict with the 7-frame figure. — [SmashWiki: Display lag](https://www.ssbwiki.com/Display_lag); [Day One Patch forum](https://www.dayonepatch.com/topic/7581-smash-ultimate-has-the-worst-input-lag-in-the-series-nearly-doubling-n64melee/)
- Brawl's in-game connection indicator ranged from "best (3 frames) to worst (more than 15 frames)" of delay. This is Brawl, not Smash 4, but it shows the series uses variable, connection-dependent delay buffers. — [SmashWiki: Frame delay](https://www.ssbwiki.com/Frame_delay)

**NEX (server side) as used by Smash 4 Wii U**
- In Pretendo's reimplementation of the Smash 4 Wii U server, the game's NEX library version is set to **3.6.0** and the game's NEX access key is `2869ba38`. The server is a PRUDP server with authentication and secure endpoints. On the secure server it registers Secure Connection, **NAT Traversal**, MatchMaking, MatchMakingExt, the **SSB4-specific MatchmakeExtension**, an **SSB4-specific DataStore**, **MatchmakeReferee** and **Ranking** protocols. — [PretendoNetwork/super-smash-bros-wiiu: nex/secure.go](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/nex/secure.go); [register_common_secure_server_protocols.go](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/nex/register_common_secure_server_protocols.go); [register_secure_server_nex_protocols.go](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/nex/register_secure_server_nex_protocols.go)
- The SSB4 DataStore methods implemented by Pretendo are GetApplicationConfig, GetProfiles, PostProfile, **GetFightingPowerChartAll** (Global Smash Power chart), GetWorldPlayReport, GetNextReplay, PrepareGetReplay, PreparePostReplay and CheckPostReplay. Files are stored in S3/MinIO. — [register_secure_server_nex_protocols.go](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/nex/register_secure_server_nex_protocols.go); [init.go](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/init.go)
- The SSB4-only MatchmakeExtension methods (IDs 36–71) cover Tournaments (GetTournament, JoinOrCreateMatchmakeSession, RegisterTournamentBot, AutoTournamentMatchmake, GetTournamentReplayIds...) and "Community Competitions" (Register/Join/Search/PostCommunityCompetitionMatchResult/GetCommunityCompetitionRanking, plus DEBUG_ variants). — [NintendoClients wiki: Matchmake Extension Protocol (SSB4)](https://github.com/kinnay/NintendoClients/wiki/Matchmake-Extension-Protocol-(SSB4))
- Background on NEX: it is Nintendo's game-server library, licensed from Quazal's Rendez-Vous. Each game server is an authentication server plus a secure server, and Wii U uses PRUDP V1 (search snippets). — [NintendoClients wiki: NEX Overview](https://github.com/kinnay/NintendoClients/wiki/NEX-Overview-(Game-Servers)); [Pretendo developer docs: NEX](https://developer.pretendo.network/overview/nex)

**PIA (Nintendo's P2P library), from Kinnay's reverse-engineering wiki**
- Pia is "a framework for setting up and maintaining peer-to-peer connections." Network types: **NEX** (game servers do matchmaking, NAT traversal often needed), **LDN** (Switch local wireless), **LAN** (UDP broadcast discovery), and **NPLN** (Pia 6+). "All peer-to-peer packets travel over UDP." — [NintendoClients wiki: PIA Overview](https://github.com/kinnay/NintendoClients/wiki/PIA-Overview)
- Topology: a group of connected consoles is a **mesh**. Each mesh has one **host**, at first the console that created it. If the host leaves, a new one is chosen by **host migration**. The host processes join requests. Join flow: matchmaking → connect to the host → join request → host accepts or rejects → join response with the member list → existing members connect to the newcomer. It is a full mesh: every station connects to every other. — [PIA Overview](https://github.com/kinnay/NintendoClients/wiki/PIA-Overview)
- NAT traversal with NEX: the game server relays "probe initiation" requests, then the consoles exchange probe requests and replies directly, then connect with the Station protocol. (The overview does not mention a relay/TURN fallback.) — [PIA Overview](https://github.com/kinnay/NintendoClients/wiki/PIA-Overview)
- Game-data protocols: **Unreliable**, **Reliable** (in-order delivery over a "reliable sliding window"), **Broadcast Reliable**, **Stream Broadcast Reliable**, **Clone** and **Sync**. Internal protocols include Station, Mesh, NAT Traversal, Keep-Alive/RTT, Monitoring and **Sync Clock**. — [PIA Overview](https://github.com/kinnay/NintendoClients/wiki/PIA-Overview); [Reliable Protocol](https://github.com/kinnay/NintendoClients/wiki/Reliable-Protocol)
- **Sync protocol** message IDs: Start/End/StartEnd/EndAlone (0x01–0x04), their acks (0x11–0x14), and Data raw/compressed (0x21/0x22). The wiki gives no payload semantics. Judging by the name and the start/end/data structure, it is Pia's frame-synchronised (lockstep) input-sharing facility, but this is not confirmed. — [NintendoClients wiki: Sync Protocol](https://github.com/kinnay/NintendoClients/wiki/Sync-Protocol)
- **Sync Clock protocol**: "Every two seconds, the station sends... to the host" its current system tick. The host replies with that tick plus a "synchronized clock, in milliseconds." The station computes RTT, takes the **median of the last 10** samples, halves it, and adds the result to the host clock value. The result is a host-controlled monotonic mesh clock. Documented for Pia 5.19–5.45 (version 0). — [NintendoClients wiki: Sync Clock Protocol](https://github.com/kinnay/NintendoClients/wiki/Sync-Clock-Protocol)
- Packet format and crypto: header layouts change with the Pia version. **Up to Pia 5.6, messages are AES-ECB encrypted with an HMAC-MD5 over the packet**; from 5.7, AES-GCM. With NEX matchmaking, the session key comes from the game server during matchmaking (128-bit AES). Messages carry a destination (station-index bitmap or constant ID), a source station index (up to 5.4: 254 = mesh host, 255 = broadcast), a protocol type and port, and a payload. — [NintendoClients wiki: Pia Protocol](https://github.com/kinnay/NintendoClients/wiki/Pia-Protocol)

### Inferences
- The netcode runs entirely on the consoles (Pia P2P mesh), and Pretendo only replaces the NEX matchmaking and NAT-traversal broker. So **netcode changes made in cross_f.rpx do not need Pretendo server changes**, as long as the NEX matchmaking calls stay compatible. Unmodified retail players and modded players must never land in the same mesh, though (see section 2).
- Session keys come from the NEX server during matchmaking. On Pretendo, a modpack therefore cannot easily open its own P2P sessions outside the game's normal NEX flow without either reusing that flow or replacing it (for example with Pia's LAN mode, if present in the binary, or with a custom transport).
- "Slowdown vs stutter": the sources describe pauses/stutter (the game waits for missing inputs), plus constant added latency from the fixed delay buffer. That pattern fits lockstep with a fixed or slowly adapting input buffer, as opposed to time-dilation.
- With lockstep, the console that hosts the Pia mesh matters only for join handling and host migration. Simulation authority is symmetric (every console simulates every frame), which is also why desyncs from mismatched mods are detected rather than corrected.

### Gaps
- **The Pia version linked into Smash 4 Wii U is not documented publicly.** It is likely pre-5.7 (AES-ECB/HMAC-MD5 era) given the 2014 release and NEX 3.6, but this is unconfirmed. The user can check it directly by searching cross_f.rpx for Pia version strings or symbols.
- No public source documents Smash 4's exact online input buffer depth (frames), whether it adapts to RTT, which Pia channel carries per-frame inputs (Sync vs Unreliable vs Reliable), or the desync-detection mechanism (checksums vs load-acknowledgement mismatch). No Core-A-style technical analysis of Smash 4 Wii U netcode was found.
- No source found on whether rendering slows down (time-dilation) vs hard-freezes under lag; the wiki wording describes "pauses"/"stuttering".

## 2. Modes, matchmaking rules, integrity checks

### Takeaway
The online menu (v1.1.0+) had With Anyone (For Fun / For Glory), With Friends, Tourney, Conquest, Spectate and Share. For Glory was restricted to Final Destination/Ω stages, no items, no customs and no Mii Fighters, with GSP-based matchmaking that was widely considered ineffective. A report-driven "For Glory Hell" pool penalised reported players. The only integrity checks documented publicly are client-side: dishonest-play detection (item checks) and desync detection that disconnects modded players.

### Cited Findings
- Menu as of v1.1.0: With Anyone, With Friends, Tourney, Conquest, Spectate, Share. "For Fun is an unranked mode that can be used with any ruleset. For Glory uses a matchmaking system based on Global Smash Power and is restricted to no items, and Ω Form stages only." Tourney "went defunct on November 8, 2017 after the discontinuation of Miiverse". Conquest "was discontinued on January 3, 2019". Share lost Miiverse-dependent options in Nov 2017, but "sharing replay data and Mii Fighters remained available." — [SmashWiki: Online play](https://www.ssbwiki.com/Online_play)
- For Glory rules: Final Destination or Ω forms, no items, customization disabled. Formats: 1v1 at 2 stocks / 5 minutes, 2v2 timed (2 minutes), and 4-player free-for-all. Team attack was off in 2v2. Mii Fighters were not allowed. An AI takes over for disconnectors. An idle kick after 15 s checks only the control stick. — [SmashWiki: For Glory](https://www.ssbwiki.com/For_Glory)
- Matchmaking: despite "some sort of matchmaking based on skill" being promised, "players found themselves matched up against other players of all skill levels at what seems to be random." "For Glory Hell": reported players were isolated into a separate pool with long waits, never officially documented. — [SmashWiki: For Glory](https://www.ssbwiki.com/For_Glory)
- Integrity checks: in 3DS v1.0.1, Peach pulling a non-vegetable item could "trigger an automatic ban for 'dishonest play'... making the game believe that the player was cheating to bring items into the mode" (fixed in 1.0.2). With a mod that adds unplayable stages to the random pool, For Glory "may have selected one of these stages". This shows that stage selection draws on the client's local data. — [SmashWiki: For Glory](https://www.ssbwiki.com/For_Glory)
- Replays are input recordings ("every input being recreated in real time"), so Nintendo blocked replays from older game versions after balance patches. — [SmashWiki: Online desynchronization](https://www.ssbwiki.com/Online_desynchronization)
- Conquest: wins were aggregated per team over a limited time, "Players detected to be sandbagging did not have their data included," and the service ended January 3, 2019. — [SmashWiki: Conquest](https://www.ssbwiki.com/Conquest)
- Version gating: "The latest version of the game must be downloaded to access online modes." — [SmashWiki: Online play](https://www.ssbwiki.com/Online_play)
- Server-side reports on Pretendo: Pretendo's Smash Wii U server stubs `CreateReportDBRecord` to `return nil` (reports are accepted and discarded). Tournament and community-competition handlers are present only as commented-out code. — [register_common_secure_server_protocols.go](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/nex/register_common_secure_server_protocols.go)

### Inferences
- The game requires the latest version for online play, and matchmaking does not segregate by content. A modpack that changes gameplay will desync, or get disconnected, against vanilla players in public For Fun/For Glory. Modded online play is practical only among players who all run the identical modpack, for example via With Friends or a custom matchmaking attribute.
- Because the report handler on Pretendo discards reports, Nintendo's report-driven "For Glory Hell" is probably not reproduced on Pretendo (inferred from code, not confirmed by Pretendo).

### Gaps
- No public source documents Smash 4 Wii U's matchmaking search criteria (attribute fields), how GSP is computed server-side, or any server-side file or hash integrity check. No evidence was found that the NEX servers ever validated game data.

## 3. Nintendo Network shutdown and its effect on Smash 4

### Takeaway
Nintendo announced the shutdown on Oct 4, 2023 and turned off Wii U/3DS online play on April 8, 2024 (00:00 UTC April 9). All official Smash 4 online features ended then. Earlier, Tourney and parts of Share had died with Miiverse (Nov 2017) and Conquest ended Jan 2019.

### Cited Findings
- "On October 4, 2023, Nintendo announced the discontinuation of the Nintendo Network service for the Wii U and Nintendo 3DS by April 2024... On January 23, 2024, Nintendo announced that the service would specifically shut down at 00:00 UTC on April 9, 2024." The infobox gives April 8, 2024 as the discontinuation date. — [Wikipedia: Nintendo Network](https://en.wikipedia.org/wiki/Nintendo_Network)
- Users still connected could keep playing after the shutdown while their consoles stayed on, some for over a month. Only system/game updates remain online; Pokémon Bank/Poké Transporter are set to end Feb 25, 2027. — [Wikipedia: Nintendo Network](https://en.wikipedia.org/wiki/Nintendo_Network)
- "Official support for all online functionality in Smash 4 ended on April 8, 2024... replacement Nintendo Network servers, primarily Pretendo, resurrect these online modes as if they were never discontinued. Emulators like Cemu, Citra, and their many forks also support online play." — [SmashWiki: Online play](https://www.ssbwiki.com/Online_play); [SmashWiki: Nintendo Network](https://www.ssbwiki.com/Nintendo_Network)
- Miiverse ended Nov 8, 2017, taking Smash 4 Tourney and Miiverse-based Share features with it. Conquest ended Jan 3, 2019. — [SmashWiki: Online play](https://www.ssbwiki.com/Online_play)

### Inferences
- Official Smash 4 online play is permanently gone, and Pretendo is the main remaining online path on both console and Cemu.

### Gaps
- None material.

## 4. Pretendo Network: Smash 4 Wii U support status, Cemu, rules on mods/cheats, known issues

### Takeaway
Pretendo has a dedicated, open-source Smash 4 Wii U server (Go, NEX 3.6). Smash went from beta (June 2024) to **public on Wii U and 3DS around April 11, 2025**. As of 2025–2026, With Anyone (For Fun / For Glory) and With Friends work, and Spectate, Conquest and Miiverse-related features do not. The player base is small (July 2026 forum report). Pretendo allows cheats and mods in private lobbies where everyone consents, and bans (account, then console) for cheating in public matches.

### Cited Findings
**Server code (primary, read in full)**
- The repo `PretendoNetwork/super-smash-bros-wiiu` describes itself as "Super Smash Bros. for Wii U replacement server. Includes both the authentication and secure servers." It needs Postgres, Pretendo account and friends gRPC services, and S3 storage, and can be self-built with Go/make. Configuration is via `PN_SSBWIIU_*` environment variables. — [README](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/README.md)
- `go.mod` uses Go 1.25 and depends on `PretendoNetwork/grpc/go v0.0.0-20260501...`, so the repo was updated in or after **May 2026**, which means active maintenance in 2026. — [go.mod](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/go.mod)
- Implemented: matchmaking (common MatchMaking/MatchMakingExt/MatchmakeExtension with a Postgres-backed matchmaking manager and friend-PID lookup for friend matches), NAT traversal, DataStore (profiles, GSP chart, world play report, replays), and registered but empty MatchmakeReferee and Ranking protocols. The code has the comment "TODO - Add legacy ranking protocol!". Tournament and community-competition handlers are commented out. — [register_common_secure_server_protocols.go](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/nex/register_common_secure_server_protocols.go); [register_secure_server_nex_protocols.go](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/nex/register_secure_server_nex_protocols.go)

**Timeline and status**

The post's snowflake ID 1910780460981968955 decodes to **2025-04-11 19:42 UTC**. — [Pretendo on X](https://x.com/PretendoNetwork/status/1910780460981968955). This conflicts with a search-engine summary claiming Wikipedia says "January 2025". The Wikipedia "Pretendo Network" page is now a redirect to Nintendo Network#Fan revival, which gives no Smash date ([Wikipedia: Nintendo Network](https://en.wikipedia.org/wiki/Nintendo_Network)). The April 11, 2025 date from the primary X post is the more reliable one.
- Unofficial Pretendo wiki (undated, search snippet): Smash for 3DS and Wii U are "Public". For Wii U: "Miiverse stage, Conquest and Spectating are not currently functional." For 3DS: "With Friends and With Anyone is functional," Spectate and Share are not. - Community activity: start.gg lists a "Pretendo Beta Tournament 2" with a Smash for Wii U event. — [start.gg](https://www.start.gg/tournament/pretendo-beta-tournament-2/event/super-smash-bros-for-wii-u/set/78070023)

**Console and Cemu access**
- Real Wii U: the full experience needs a console hack ("Aroma" with Pretendo's Inkay plugin). A hackless SSSL option exists with limited functionality, reportedly firmware 5.5.5+ only (search snippets). — [Pretendo FAQ / guides via search](https://videogames.si.com/guides/wii-u-pretendo-2024)
- Cemu: Pretendo's Cemu docs say "Cemu 2.0 has official built-in support for Pretendo as of October 10, 2022". When dumping user account files, "ensure you select your PNID". **Rules on mods, cheats and bans**
- Pretendo Online Services Code of Conduct (posted about Oct 2026, roughly 18 days before research per the search snippet): "cheats or mods that don't harm the online experience (cosmetic cheats, optimization mods, save editing, etc.) are allowed to be shared and discussed unless otherwise forbidden"; "Hacks are permitted in private lobbies if everybody consents to using hacks"; excessive flashing-light abuse gets an "immediate console ban". The Mario Kart section bans speed, item and custom-track hacks in public lobbies and allows them in consenting private Communities (search snippet). — [Pretendo forum: Online Services Code of Conduct](https://forum.pretendo.network/t/pretendo-network-online-services-code-of-conduct/30557)
- Pretendo FAQ: cheating is bannable when it gains an unfair advantage or disrupts people who did not consent (public matches). Pretendo "regularly appl[ies] account and console bans to both Wii U and 3DS systems". A forum answer adds: "your first ban will usually be an account ban and second will be a console ban". Pretendo says it uses measures that make traditional ban evasion ineffective (search snippets). — [Pretendo forum FAQ thread](https://forum.pretendo.network/t/frequently-asked-questions-regarding-pretendo-network-and-pretendo-forums/4339); [Pretendo forum FAQ](https://forum.pretendo.network/faq)
- An earlier Pretendo Mastodon post (2023): "there isn't really a way for us to implement an anti-cheat system", so enforcement relies on user reports (search snippet). — [Pretendo Mastodon](https://mastodon.pretendo.network/@pretendo/110657739358845139)

### Inferences
- A gameplay-changing modpack (new fighters and stages, moveset and physics changes) is, under Pretendo's rules, acceptable only in private, consenting lobbies (With Friends among modpack users). Public With Anyone use would risk bans and would desync against vanilla players anyway.
- Pretendo's server code is open source, Go-based and self-hostable. A modpack-specific matchmaking server (forked from `super-smash-bros-wiiu`) is technically feasible. Cemu's "Custom" network service (section 5) can point at it, and consoles could be redirected with a patched Inkay-style plugin. That would isolate modpack players from vanilla ones.

### Gaps
- Pretendo's own progress page and blog could not be read directly. No official per-feature list for Smash 4 Wii U as of late 2026 was found beyond the snippets above.
- No source found documenting a Smash 4-specific section of Pretendo's code of conduct, or any Smash-specific ban wave.
- Specific Smash 4-on-Pretendo bug reports (desync frequency, room-creation limit details) are only third-hand.

## 5. Cemu: online requirements, netplay/savestates, Cemu ↔ Wii U crossplay

### Takeaway
Cemu supports real Nintendo Network/Pretendo-style online play (not netplay). It needs console-dumped `otp.bin`, `seeprom.bin`, certificate files and an account linked to an NNID/PNID. Its Network Service selector offers Offline, Nintendo, Pretendo and **Custom** (`network_services.xml` URL overrides). Cemu has no built-in netplay, lockstep or savestate feature, and no maintained savestate fork was found. Cemu and real Wii U consoles share the same Pretendo servers and accounts, so crossplay works in principle.

### Cited Findings
- Cemu's settings UI (current `main` source) offers the network service choices `{ "Offline", "Nintendo", "Pretendo", "Custom" }`. The Custom tooltip reads "Connect to a custom Network Service (configured via network_services.xml)", and Custom is greyed out unless that XML exists. — [Cemu source: GeneralSettings2.cpp](https://raw.githubusercontent.com/cemu-project/Cemu/main/src/gui/wxgui/GeneralSettings2.cpp)
- `network_services.xml` can override the ACT, ECS, NUS, IAS, CCSU, CCS, IDBE, BOSS, TAGAYA and OLV URLs. — [Cemu source: NetworkSettings.cpp](https://raw.githubusercontent.com/cemu-project/Cemu/main/src/config/NetworkSettings.cpp)
- Online requirement checks in Cemu: the status strings are "OTP.bin or SEEPROM.bin is missing", "OTP and SEEPROM present but no certificate files were found", "Selected account is not linked to a NNID or PNID", and "Selected account is a valid online account". Cemu links to an "Online play tutorial" at cemu.info/online-guide. — [GeneralSettings2.cpp](https://raw.githubusercontent.com/cemu-project/Cemu/main/src/gui/wxgui/GeneralSettings2.cpp)
- Dumping: guides point to the Cemu Online Play Guide (cemu.cfw.guide), which uses a homebrew dumper on a real Wii U to extract `otp.bin`, `seeprom.bin`, the account's `usr`/`sys` files and certificates. Pretendo's docs say to select the PNID when dumping account files (search snippets). — [RetroDECK Cemu guide](https://retrodeck.readthedocs.io/en/latest/wiki_emulator_guides/cemu/cemu-guide/); [Pretendo docs: Cemu](https://pretendo.network/docs/install/cemu)
- Version notes: Pretendo says Cemu 2.0 had built-in Pretendo support from Oct 10, 2022; the Pretendo FAQ says "Cemu 2.1 officially supports Pretendo" (search snippets). RetroDECK's 2024 notes said results were "still mixed" for the 2.0-72 experimental build. — [Pretendo docs: Cemu](https://pretendo.network/docs/install/cemu); [RetroDECK Cemu guide](https://retrodeck.readthedocs.io/en/latest/wiki_emulator_guides/cemu/cemu-guide/)
- Crossplay: per a third-party 2026 guide, "Pretendo works on hardware too (via a homebrew patcher called Inkay). The Pretendo account is the same — you can use the same username on both Cemu and a real Wii U." The same guide suggests UPnP or port forwarding when "Lobby found but game disconnects after a few seconds" (it lists "UDP 16000–16030"; that port range is unverified and the source is low-authority). — [EmuDesk 2026 guide](https://emudesk.com/issues/cemu-pretendo-network-wii-u-online-2026)
- SmashWiki lists Cemu among emulators where Wi-Fi lag occurs and says Cemu supports Smash 4 Wii U online play. — [SmashWiki: Wi-Fi lag](https://www.ssbwiki.com/Wi-Fi_lag); [SmashWiki: Nintendo Network](https://www.ssbwiki.com/Nintendo_Network)

### Inferences
- Cemu online play is the console's own online stack, emulated: the game's Pia P2P traffic goes from the Cemu host straight to peers over UDP. Cemu therefore behaves like a console on the network, and **Cemu ↔ Wii U Smash 4 matches use the same delay-based netcode**. Cemu cannot improve it unless the game code is patched, for example through the user's cross_f.rpx caves or Cemu graphic-pack patches.
- Lockstep requires bit-identical simulation. Cemu's CPU recompiler and floating-point behaviour would have to match real Espresso hardware exactly for Cemu ↔ console matches to stay in sync. Community reports of "occasional desyncs" (EmuDesk) are weak evidence that mismatches happen, but they are unconfirmed and their cause is unknown.
- No Cemu savestates were found, so any rollback scheme for Smash 4 would need in-game state save/restore implemented inside the RPX, not by the emulator.
- The "Custom" network service gives Cemu users a supported, no-hack way to point at a self-hosted Pretendo-derived server for a modpack.

### Gaps
- No Cemu netplay or savestate feature or maintained fork could be confirmed. The search found no savestate fork, and Cemu's official UI offers none. Absence is not proof; the user may want to search GitHub directly.
- Cemu ↔ real Wii U Smash 4 desync rates were not found in any reliable source.
- The exact list of certificate files Cemu requires (e.g. `ccerts/`/`scerts/` from the Wii U system titles) was not retrieved from the online guide (site unreachable).

## 6. Private-server / LAN-tunnelling approaches; does Smash 4 Wii U have a LAN mode?

### Takeaway
Smash 4 for **Wii U has no LAN or local wireless (multi-console) mode**. Local Wireless is a 3DS and Ultimate feature only. The available routes for Wii U online play today are Pretendo (public servers), a self-hosted Pretendo stack (open-source Go servers), and Cemu's "Custom" network service. No evidence was found of XLink Kai or LAN-tunnelling being used for Smash 4 Wii U, which makes sense since it has no LAN mode to tunnel.

### Cited Findings
- "Local Wireless is the function in for Nintendo 3DS and Super Smash Bros. Ultimate in which players can play with other players via wireless connection." The page has sections only for 3DS and Ultimate. — [SmashWiki: Local Wireless](https://ssbwiki.com/Local_Wireless)
- Nintendo's 2014 Smash Direct said 8-player Smash on Wii U is offline-only (search snippet). — [Nintendo Life: 8 player smash mode confirmed](https://www.nintendolife.com/news/2014/10/8_player_smash_mode_confirmed_for_wii_u_super_smash_bros)
- Contrast: Pokkén Tournament (Wii U) does have a hidden two-console "LAN Battle" mode, so Wii U-era Pia-based games could ship LAN modes; Smash 4 did not. — [Serebii: Pokkén LAN Battle](https://serebii.net/pokken/lanbattle.shtml)
- Pia itself supports a **LAN** network type (UDP broadcast discovery). For LAN in Pia 5.9–6.30, the session key is derived via HMAC-SHA256 with a game-specific key. — [PIA Overview](https://github.com/kinnay/NintendoClients/wiki/PIA-Overview); [Pia Protocol](https://github.com/kinnay/NintendoClients/wiki/Pia-Protocol)
- Self-hosting: Pretendo's Smash Wii U server is buildable with Go/make and configured via environment variables (Postgres, account and friends gRPC, S3). A Pretendo forum thread "Host your own Pretendo Network server" exists (not readable here). — [super-smash-bros-wiiu README](https://raw.githubusercontent.com/PretendoNetwork/super-smash-bros-wiiu/master/README.md); [Pretendo forum: Host your own](https://forum.pretendo.network/t/host-your-own-pretendo-network-server/589)

### Inferences
- A modpack-only online setup is realistic without LAN tunnelling: a forked or self-hosted Pretendo Smash server, plus Cemu's Custom network service and a patched redirect on consoles, would keep modpack players in their own matchmaking pool. That avoids Pretendo's public-lobby rules and desyncs against vanilla players.
- Whether the Smash 4 RPX contains Pia's LAN-mode code (dead-stripped or not) is unknown. If it does, it could be a basis for a direct-connect mode. If not, a netcode upgrade would need its own transport, or would reuse the NEX/Pia path.

### Gaps
- No reports found of XLink Kai, ZeroTier/LAN tunnelling, or private non-Pretendo servers being used specifically for Smash 4 Wii U.
- Whether any community fork of Pretendo's Smash server exists for modded play: not found.
